# Project security extension

Target: `apps/intel/src/components/project-security.tsx`, `/app/projects/:id/security`.

Mode: Operate. Small software teams inspect four repository configuration checks, record their self-reported exposure context, and choose a relevant response playbook. The original response desk, Satoshi, purple/pink identity, light theme, source provenance, and user-attested response boundaries remain fixed.

Composition: project identity and environment; persistent project destination links; repository baseline rows and read provenance; separate context form; related response playbooks below. This is a precisely scoped extension of the established project workflow, not an open identity or composition tournament. The user asked to build the researched scope; no mockup choice is pending.

Research: inspected Mobbin Supabase Security Advisor, Base44 expanded security issue, Browserbase project settings, and Plane project settings. Exact links and accepted/rejected patterns are in `docs/BASELINE-DESIGN.md`.

Quality bar: source paths and read commit must remain inspectable; collection, sync, source availability, and self-reported answers stay independent. No aggregate security grade. Unknown is a useful state. No automatic exposure inference or finding dismissal. Native details, explicit labels, inline save errors, and visible focus work in dark, light, desktop, and mobile. Long hashes/paths wrap inside their own area.

Verification handoff: parent captures desktop/mobile/light and runs an independent finish review after integration. Child performs scoped type/style checks and one mechanical detector run; no invented browser verification is recorded here.
