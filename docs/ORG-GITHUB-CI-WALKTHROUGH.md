# Organization → GitHub → CI review

Completed through the local browser on 5 November 2026. The API, sign-in, organization/project storage and CI parsing were real. Repository transport used an explicitly labelled synthetic fixture. No live GitHub grant, code execution, repository patch or external advisory scan occurred.

1. **Create an organization.** Organization settings → Create another organization → `Launch walkthrough · demo`. The saved page showed the new organization selected, the current account as its first owner and one member. Owner/admin/member roles apply within each organization; projects and responses inherit that scope. Capture: `.impeccable/review/ci/flow-01-organization.png`.
2. **Choose the connected GitHub account and repository.** Projects → Add project → Repository. The page explained that the provider connection stays personal while project inventories and responses are shared with the selected organization. The local preview disabled live Connect and labelled its existing account as synthetic. Select `synthetic/ci-checkout`. Capture: `flow-02-github.png` in the same folder.
3. **Select branch and inventory.** Set `Checkout service · demo`, Development, branch `main`, discover files and select `package.json`. Reads use one immutable commit and do not execute repository code. A real project would normally select its supported lockfile for resolved versions. Capture: `flow-03-inventory.png`.
4. **Review before saving.** The review showed repository, branch, the full 40-character commit, one exact synthetic package/version and the target organization. Create project and assess saved the project; the preview intentionally does not pretend a real advisory assessment succeeded. Capture: `flow-04-review.png`.
5. **Review CI dependency checks.** The saved Security baseline showed 11 references in five files. Expand `actions/checkout`: `.github/workflows/ci.yml:9`, reference `v4`, Mutable reference, why it needs review, a concrete pin/lock recommendation and a source link bound to the checked commit. Pinned, lock-entry, local and unknown states remain distinct. Recheck succeeded and updated the read time; a page reload retained the result. Filtering Mutable reference showed four of eleven entries, including a reusable workflow, GitLab include and container image. Captures: `flow-05-ci-overview.png`, `flow-05-ci-evidence-dark.png` and `flow-06-ci-evidence-light.png`.

Open the saved local project at `http://localhost:3003/app/projects/cmw3od4ki00036kvjppjqedsm/security`. It uses the private synthetic preview account; credentials are kept in the local fixture and are not part of this document.

For a live account, the first Connect action opens the provider's real authorization/installation flow. Registered application credentials, callback URLs, selected-repository permission and the user's grant must exist before that step can be demonstrated. The local fixture does not prove those external conditions. Continuing management is under Connections: sync/pause, access refresh and disconnect use current organization roles and the connector's current authority. Recheck reads the imported commit; import/sync is the separate action that moves inventory to a new branch commit.

Configuration evidence does not prove that CI ran, branch protection is enforced, a dependency is trustworthy, a version is deployed or vulnerable code is reachable. The free offline CI skill and its download checks are described in `CI-ORG-VERIFICATION.md`.
