# Wisesama v2 admin design research

The user requested management of users, advisories, intelligence sources, public email subscriptions, and failed jobs, with proper Mobbin research for each flow. This implementation is a dedicated `/admin` experience within `apps/intel`, separate from the customer workspace and the preserved Dotsama admin. It inherits the selected Response desk identity: Satoshi, charcoal surfaces, purple actions, light mode, restrained density, and explicit evidence boundaries.

Every surface is Operate. The administrator needs to find a record, understand its state and consequences, perform one scoped action, and inspect the result. No illustration is needed; live record identity, state, provenance, and audit history supply the useful content. No reference-product image or asset ships in the interface.

## Weak or unrelated results

The first subscription search returned New York Times personal newsletter preferences and Klaviyo sign-up forms. Those did not establish an operator consent record, so a narrower subscriber-profile search was run and the actual Klaviyo suppression view was used. Eventbrite's personal email preferences were also excluded from the operator design.

The broad security searches returned a consumer Revolut Security Hub and an empty Base44 security screen. These were not evidence for vulnerability editing and are not used as such. incident.io's record/review layout is used for structure only; Wisesama's data contract determines immutable advisory facts and scoped editorial changes.

The Base44 Data result was a collection picker rather than source health, so it was excluded. The useful source references were the actual incident.io source rows and Gumloop's inspected pause transition.

## Flow and state contracts

- **Access:** sign in with an existing account, then fetch the live V2 admin session. Dotsama roles never imply V2 access. A 401/403 from any admin request clears the protected admin content; logout unmounts it. Unavailable access checks have a distinct error heading. No sign-up or privilege-grant action is exposed.
- **Lists:** explicit search/filter submission, stable cursor paging, inspectable first-column record links, readable empty states, retained failure information, and a clear route back to the first page. List filters are preserved on record/back links. Filters reset cursor position.
- **Records:** identity and state before mutable controls. Full record pages avoid compressing context into a narrow list inspector. Exact source timestamps, unknown states, blocked retry reasons, and the result of the last operation remain visible.
- **Changes:** a reason of at least 20 characters, an effect statement, and an explicit confirmation precede writes. Revision conflicts preserve the draft, disable another stale save, and offer an expressly named discard/reload action. Reasons and evidence fields discourage secrets and unrelated sensitive data.
- **Jobs:** queueing is an acknowledged state, not execution. A queued job can be inspected and explicitly run. HTTP 200 with a failed outcome stays failed. A running job cannot be launched again; sent/blocked mail has no UI resend shortcut. Scheduler configuration remains a deployment condition.
- **Audit:** actions carry actor, target, reason, and time. Detail views identify their records as recent diagnostic history; the paginated audit log offers older records. There are no audit edit/delete controls.

## Responsive composition

Desktop uses an independent admin sidebar and a restrained title/filter/table hierarchy. Record pages use a reading area plus action area when space permits; at 1200px and below action sections move beneath the record. At 900px the sidebar becomes a horizontally scrollable named navigation. At 650px the record/action areas become one column and labels remain adjacent to fields. At 650px and below, each native table row keeps its identity and shows the other columns as labelled facts, including status, outcomes and timestamps. Desktop alternatives are hidden in the mobile accessibility tree, and mobile facts are hidden on desktop. Wider tables use named horizontal-scroll regions; only actual overflow adds a visible scrolling instruction and keyboard focus. Attempt-history dates wrap within their reading panel. Source, error, reason, and identifier strings wrap within their own area.

Theme roles are inherited from Wisesama. Controls use native inputs/selects/checkboxes/details where appropriate; focus, text selection, scrollbar colors, and disabled/loading/error states use existing tokens. No new color palette, decorative chart, grade, illustration, or success guarantee is introduced. Admin metadata explicitly disables indexing/following even if public indexing is enabled later.

## Verification handoff

This child implementation owns scoped TypeScript/style checking and one mechanical detector pass. The parent owns real protected API/database verification, local fixture creation/cleanup, the bounded desktop/mobile and dark/light browser capture pass, and independent finish-review/documentation handoffs. Source inspection and a type-safe DTO do not establish live provider authorization, real email delivery, production scheduling, or production readiness.

The source record labels Collection and Check state separately, including when both values are paused. A previous successful attempt remains a timestamped historical fact; resuming collection does not imply a fresh successful check. These refinements address the independent finish review in `ADMIN-FINISH-REVIEW.md`.
